# AutoDL GPU gate — 操作员提供的控制台证据

来源：操作员于 2026-09-19 粘贴的终端输出。原始日志和 checkpoint 仍在 AutoDL 的 `/root/autodl-tmp/ProbeGRPO/outputs/` 下。这是对日志的整理，不是独立重跑实验。远端 ProbeGRPO 的准确 revision 和完整 manifest 仍需另存。

## 运行环境

- NVIDIA GeForce RTX 4090，GPU gate 时显示 49,140 MiB；驱动版本 595.71.05。
- verl `cf14ded3a448107e70a206fd201817cc1cbae348`，Python 3.12.3。
- torch 2.11.0+cu130、Transformers 5.9.0、vLLM 0.24.0、flash-attn 2.8.3。
- 运行时将 NumPy 覆盖为 2.3.5；从锁定的 NumPy 2.4.6 换下后，`uv pip check` 通过。
- 模型：Qwen/Qwen3.5-2B，下载快照 `15852e8c16360a2fea060d615a32b45270f8a8fc`（实际加载的 revision 未单独证明）。

## 证据与局限

1. 首次五步 GRPO 用时 9 分 41 秒。最后一批 reward/advantage 为零，所有 response 都达到 256-token 上限。退出时出现 DataLoader worker 清理错误。
2. 显式恢复时加载了 step-5 的模型、优化器、随机状态和学习率调度器；随后完成 step 6 并保存新 checkpoint。退出时同样出现清理错误。step-6 模型状态约 8.5 GiB，优化器状态约 357 MiB。完整 FSDP checkpoint 不是仅含 adapter 的导出。
3. 日志中的 32 行由 8 条真实轨迹和 24 条合成 padding 行组成。此 verl revision 会把 actor 的 `ppo_mini_batch_size` 乘以 rollout.n。设为 8 会要求 32 行；设为 2 时需要的倍数为 8。
4. 一个新鲜单步 signal smoke 使用 mini-batch 2、dataloader workers 0、response 上限 1024、最大批量 token 数 2048。观察到正好 8 行 JSONL，且正常退出。

Signal smoke 指标（单个训练 batch，不是评估）：reward 均值 0.75；advantage 最小值 -1.499997/最大值 0.499999；actor loss -0.073011；梯度范数 0.800695；actor 最大分配显存 18.84 GiB、预留 20.82 GiB（不是整个进程或 GPU 的峰值）；step 用时 172.03 秒，权重同步 73.81 秒。不能据此声称 ProbeGRPO 有提升。

五步/恢复测试与修正后单步测试使用了不同设置。最终修正后的默认配置还没有重新跑完五步。将 DataLoader worker 设为 0 避免了已观察到的子进程退出故障，但尚不能说明子进程为何被终止。
