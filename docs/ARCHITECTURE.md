# Architecture

## Design goal

ProbeGRPO isolates the research idea from the training framework. The package can test replay,
selection, probing, and advantage shaping without importing torch. RAGEN/verl is an adapter at the
edge, not a dependency of the core.

## Data flow

1. The normal Agent-RL runner produces `K` trajectories for one task group.
2. Each assistant turn becomes a `TurnRecord`. Its `action_prefix` excludes the current action, and
   `token_indices` covers only tokens generated by that assistant turn.
3. An `AnchorScheduler` selects at most `budget` eligible turns across the group.
4. `CounterfactualProber` creates two fresh environments and replays the same prefix in both.
5. It verifies state hash and observation equality before executing different forced actions.
6. Both branches use the same suffix sampling seed and return a `ProbeResult`.
7. The scheduler observes `abs(delta) / additional_rollout_tokens`.
8. `blend_probe_advantages` standardizes valid deltas and adds them only at selected token indices.

## Public contracts

### `ReplayableEnv`

```python
reset(task_id: str, seed: int) -> ReplayState
step(action: str) -> ReplayState
replay(task_id: str, seed: int, action_prefix: Sequence[str]) -> ReplayState
```

The reset operation must be deterministic. Replay is implemented as reset plus public actions; this
avoids copying opaque browser/database objects.

### `TurnRecord`

The important invariant is:

```text
replay(task_id, seed, action_prefix).state_hash == state_hash
```

If the invariant fails, the probe is invalid and contributes zero local credit.

### Torch/RAGEN batch fields

```text
advantages        float [batch, tokens]
probe_turn_masks  bool  [batch, anchors, tokens]
probe_deltas      float [batch, anchors]
probe_valid       bool  [batch, anchors]
```

The adapter computes the adjustment without modifying trajectory rewards or unrelated turns.

## Scheduler behavior

- `random`: matched-cost control.
- `entropy`: cheap uncertainty heuristic.
- `linear_ucb`: predicts useful credit per extra rollout token with uncertainty bonuses.

LinearUCB uses seven bounded features: entropy, inverse log-probability margin, normalized turn
position, prior invalid-action ratio, legal-action count, suffix cost, and final reward. The first 20
updates or 200 valid probes use position-stratified random selection.

## Failure behavior

- no alternative action: skip;
- illegal factual or alternative action: skip;
- prefix replay error: skip and retain the error class in `skipped_reason`;
- state mismatch: skip when strict mode is enabled;
- no valid probe deltas: return the original GRPO advantage;
- equal probe deltas: add zero relative credit;
- budget zero: exactly recover GRPO.

## Current implementation boundary

The core pipeline and torch blending adapter are implemented and CPU-tested. A real RAGEN run still
needs a rollout hook that converts RAGEN histories into `TurnRecord`s and sends branch suffixes back
through the current model server. This hook is intentionally kept outside RAGEN's old pinned
dependencies because its released `vllm==0.8.2` stack cannot serve Qwen3.5. See
[GPU_RUNBOOK.md](GPU_RUNBOOK.md) before attempting GPU installation.
